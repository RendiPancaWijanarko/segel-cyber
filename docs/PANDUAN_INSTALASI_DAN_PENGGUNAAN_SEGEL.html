PETUNJUK KEAMANAN DAN KEPATUHAN PANGKALAN
Sistem SEGEL dirancang untuk beroperasi di lingkungan terisolasi penuh (air-gapped). Selama pengoperasian lokal, sistem tidak memerlukan sambungan internet keluar. Seluruh komunikasi kecerdasan buatan dibatasi secara tegas pada antarmuka loopback 127.0.0.1:11434. Kunci privat kriptografis sintetis yang disertakan pada direktori pengujian hanya diperuntukkan bagi keperluan demonstrasi dan dilarang digunakan pada instalasi produksi militer.
PRINSIP PERTAHANAN LAPIS-GANDA (DEFENSE-IN-DEPTH)
Setiap perubahan konfigurasi IT/OT wajib melalui pengesahan M-dari-N perwira komando. Model kecerdasan buatan (AI) hanya bersifat penasihat (advisory) dan dibatasi maksimal pada tingkat peringatan (warn). AI tidak pernah menandatangani rilis dan tidak dapat membatalkan aturan kebijakan deterministik.

BAB I. RINGKASAN EKSEKUTIF & KONSEP DOKTRIN OPERASIONAL

1.1 Latar Belakang Kebutuhan Pertahanan Siber TNI AD

Satuan operasional TNI Angkatan Darat mengelola infrastruktur komando dan kendali kritis, sistem telekomunikasi taktis, stasiun radar, serta aset Operational Technology (OT) di medan operasi terdepan. Ancaman siber modern terhadap rantai pasok perangkat lunak (software supply-chain attacks)—seperti penyisipan pintu belakang (backdoor), manipulasi skrip pembaruan firmware, dan eskalasi hak akses ilegal—dapat melumpuhkan sistem pertahanan negara apabila pembaruan digelar tanpa validasi yang ketat.

SEGEL (Sistem Edar Gelar Elektronik Lapis-ganda) hadir sebagai solusi gerbang pengamanan rilis independen yang menjamin doktrin operasional:

“NO EVIDENCE, NO DEPLOYMENT”
(Tidak ada artefak atau konfigurasi yang dapat digelar ke stasiun kerja operasional satuan tanpa rantai bukti kriptografis yang utuh dan terverifikasi secara matematis)

1.2 Rantai 5 Stempel Kriptografis Berantai

SEGEL menegakkan lima gerbang verifikasi berurutan sebelum suatu paket konfigurasi memperoleh status promosi paspor umum (General Passport) untuk disebarkan ke unit penerima lapangan:

Stempel 1
ASAL-USUL
Builder (Pabrik)

Atestasi sumber kode, integritas biner, identitas pembangun.

Stempel 2
INSPEKSI
Inspector + AI

Ekstraksi kapabilitas, audit kebijakan, klasifikasi niat rilis.

Stempel 3
PERSETUJUAN
Komando (2-of-3)

Persetujuan multi-pihak air-gapped, pengikatan pengakuan.

Stempel 4
PENCATATAN
Buku Transparansi

Pohon Merkle RFC 6962 & tanda tangan saksi independen.

Stempel 5
PENGUJIAN
Kanari & Penerima

Uji kesehatan kanari, anti-rollback, gelar atomik 10-langkah.

1.3 Karakteristik Keamanan Terdepan

  • Kriptografi Standar Terbuka (Non-Custom): Menggunakan RFC 8032 Ed25519 dan SHA-256 melalui pustaka standar PyCA Cryptography tanpa algoritma ciptaan sendiri.
  • Prinsip Fail-Closed: Setiap ketidakcocokan tanda tangan, anomali hash, kegagalan kebijakan, atau timeout sistem menghasilkan penolakan mutlak seketika tanpa perubahan status sistem.
  • Model AI Penasihat Terisolasi: Model AI hanya berhak memberikan advis tingkat keparahan warn, tidak memiliki akses ke kunci privat, dan diverifikasi integritas prompt-nya menggunakan pembekuan hash SHA-256.
  • Kemandirian Lingkungan Terputus: Unit penerima di pos terdepan dapat melakukan verifikasi penuh tanpa koneksi ke server pusat.

Komponen Kebutuhan Minimum Rekomendasi Operasional Satuan

  1. Sistem Operasi: Microsoft Windows 10/11 (64-bit) dengan Windows PowerShell 5.1 atau PowerShell 7+, atau distribusi Linux (Ubuntu 22.04 LTS / Debian 12 / Rocky Linux 9).
  2. Runtime Python: Python versi 3.14.6 (terverifikasi penuh pada stasiun kerja pengembangan) atau Python 3.12+ (kompatibel secara sintaks).
  3. Git CLI: Untuk manajemen versi kode sumber dan pelacakan riwayat komit.
  4. Peramban Web Modern: Microsoft Edge, Google Chrome, atau Mozilla Firefox untuk mengakses antarmuka grafis Meja Rilis (Release Desk).
  5. Ollama Runtime (Opsional untuk AI Aktif): Layanan Ollama lokal untuk mengeksekusi model sumber terbuka qwen3:4b.
JAMINAN ISOLASI SISTEM
Seluruh rangkaian pengujian (436 uji) dan operasi dasar gerbang rilis SEGEL dapat berjalan 100% tanpa internet. Jika Ollama tidak diinstal atau dinonaktifkan, SEGEL secara otomatis beralih ke mode deterministik (Rule B1b) tanpa penurunan standar keamanan pengujian.

BAB IV. PANDUAN INSTALASI LANGKAH-DEMI-LANGKAH

4.1 Langkah 1: Klon Repositori Kode Sumber

Buka terminal PowerShell dan navigasikan ke direktori kerja yang diinginkan:

git clone <url-repositori-segel> segel-cyber
cd segel-cyber

4.2 Langkah 2: Pembuatan Virtual Environment Python

Pastikan versi Python terdeteksi dengan benar, kemudian buat virtual environment terisolasi: 

# Memeriksa versi runtime Python
python --version
# Output terverifikasi: Python 3.14.6

# Membuat virtual environment terisolasi pada direktori .venv
python -m venv .venv

4.3 Langkah 3: Aktivasi Virtual Environment

Aktifkan virtual environment pada sesi PowerShell Anda:

# Mengaktifkan sesi virtual environment Windows
.\.venv\Scripts\Activate.ps1

# Catatan: Jika muncul kendala kebijakan eksekusi skrip, jalankan:
# Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Tanda (.venv) akan muncul di awal baris perintah terminal yang menandakan isolasi telah aktif.

4.4 Langkah 4: Instalasi Dependensi Pengembang (Local Editable)

Lakukan instalasi paket SEGEL bersama seluruh dependensi pengujian dan pengembangannya: 

pip install -e ".[dev]"

Perintah di atas akan membaca konfigurasi pyproject.toml dan memasang seluruh dependensi resmi (cryptography, fastapi, pydantic, jinja2, pillow, qrcode, uvicorn, hypothesis, pytest, bandit, ruff, mypy).

4.5 Langkah 5: Verifikasi Integritas Prompt & Repositori

Sistem SEGEL memvalidasi bahwa templat prompt inferensi AI tidak mengalami penyusupan melalui verifikasi hash SHA-256 terhadap berkas pembekuan docs/ai_prompt_freeze.txt: 

python -c "from src.inspector.ai.prompt import verify_prompt_integrity; print('Integritas OK' if verify_prompt_integrity() else 'TERKOMPROMISI')"

Jika integritas terjamin, terminal akan menampilkan konfirmasi Integritas OK.

BAB V. PENYIAPAN & INFERENSI SUBSISTEM AI LOKAL

5.1 Arsitektur Penasihat AI (Qwen3-4B via Ollama Loopback)

Subsistem AI pada SEGEL dirancang dengan batasan keamanan ketat:

  • Isolasi Loopback: Inferensi hanya diarahkan ke http://127.0.0.1:11434. Tidak ada lalu lintas ke jaringan eksternal.
  • Tanpa Penyimpanan Kunci (Zero Key Exposure): Pekerja inferensi dieksekusi dalam subproses steril tanpa variabel lingkungan kredensial.
  • Pemberian Peringatan Tertinggi (Capped at Warn): AI tidak memiliki hak eksekutif untuk menolak atau meloloskan rilis secara sepihak.

5.2 Langkah Penyiapan Ollama & Penarikan Model

  1. Unduh dan Pasang Ollama:
    Pasang aplikasi Ollama untuk Windows. Pastikan layanan berjalan di latar belakang (ikon baki sistem aktif).
  2. Tarik Bobot Model Terbuka Qwen3-4B: 
    ollama pull qwen3:4b
    Catatan: Ukuran bobot model sekitar 2.6 GB. Bobot disimpan secara lokal pada mesin host dan tidak dimasukkan ke dalam repositori kode git.
  3. Uji Kesiapan Model melalui Skrip Pra-Terbang (Preflight Script): 
    powershell -ExecutionPolicy Bypass -File scripts/demo_ai_preflight.ps1
    Skrip akan mengirimkan permintaan pemanasan (warm-up request) dengan parameter keep_alive 30m, memverifikasi keterisian memori GPU/RAM via ollama ps, serta mencetak latensi inferensi dalam milidetik.

5.3 Pengaturan Variabel Lingkungan Kontrol

Perilaku subsistem AI dapat dikendalikan melalui variabel lingkungan sistem:

Variabel Lingkungan Nilai Baku Deskripsi Fungsi
SEGEL_AI_ENABLED 1 (atau 0) Mengaktifkan (1) atau menonaktifkan (0) inferensi AI penasihat. Jika 0, sistem beralih ke aturan deterministik B1b.
SEGEL_AI_HOST http://127.0.0.1:11434 Alamat antarmuka loopback Ollama lokal.
SEGEL_AI_TIMEOUT_SECONDS 3.0 Batas waktu tunggu inferensi. Jika melampaui, sistem gagal aman (fail-closed) memunculkan peringatan timeout.

BAB VIII. ALUR KERJA SIMULASI OPERASIONAL LAPANGAN

8.1 Babak 1: Rilis Standar Bersih (Pembaruan Firewall Pangkalan)

  1. Pembuatan Paket (Pabrik): Paket konfigurasi firewall pangkalan ditandatangani menggunakan kunci pembangun yang sah.
  2. Inspeksi Kebijakan: Mesin inspeksi mengekstraksi aturan port firewall dan memvalidasi terhadap aturan keamanan. Hasil inspeksi: LULUS (PASS).
  3. Persetujuan Komando: 2 dari 3 perwira komando menandatangani persetujuan secara terpisah.
  4. Pencatatan Buku Transparansi: Atestasi dicatat ke dalam pohon Merkle; saksi menerbitkan tanda tangan bersama.
  5. Promosi Paspor: Paket rilis resmi dipromosikan ke status General Passport dan siap digelarkan.

8.2 Babak 2: Penolakan Keras Eskalasi Hak Istimewa (Kebijakan PRULE-001)

  1. Skenario Serangan: Paket konfigurasi ilegal mencoba menyisipkan perintah eskalasi hak istimewa (root privileges / penambahan akun sudo gelap).
  2. Deteksi Gerbang Inspeksi: Kebijakan deterministik PRULE-001 secara tegas mendeteksi pelanggaran batas hak akses.
  3. Respon Sistem: Penerbitan status TOLAK (REJECT) seketika. Rilis dibekukan dan tidak dapat dilanjutkan ke meja persetujuan komando.

8.3 Babak 3: Peringatan AI & Pengikatan Pengakuan (Warning Acknowledgement)

  1. Skenario Ketidaksesuaian Intensi: Manifest rilis mengklaim tujuan perbaikan kosmetik biasa, namun muatan teknis mengandung perubahan rute jaringan taktis.
  2. Deteksi Penasihat AI: Model bahasa Qwen3-4B mendeteksi ketidaksesuaian intensi dan menerbitkan temuan PERINGATAN (WARN) kategori L6.
  3. Kewajiban Pengakuan Kriptografis: Komando tidak dapat menandatangani persetujuan tanpa menyertakan acknowledgement_digest yang mengikat tanda tangan komando dengan teks peringatan AI secara eksplisit.

8.4 Babak 4: Penerimaan Terisolasi & Gelar Atomik 10-Langkah

  1. Verifikasi Paspor Mandiri: Node penerima pos depan memvalidasi tanda tangan 5 stempel dan bukti konsistensi Merkle secara offline.
  2. Pencegahan Rollback: Sistem memeriksa nomor urut rilis monotonik untuk menggagalkan upaya serangan pemunduran versi (rollback attack).
  3. Eksekusi Gelar Atomik: Penerapan konfigurasi dilakukan melalui tahapan persiapan, pencatatan jurnal pemulihan, penggantian berkas atomik, verifikasi integritas, hingga penuntasan rilis.

BAB X. PROSEDUR PENGHENTIAN & PEMULIHAN LINGKUNGAN

10.1 Prosedur Penghentian Layanan (Graceful Shutdown)

Pada jendela terminal yang menjalankan Meja Rilis (Uvicorn), tekan kombinasi tombol Ctrl + C untuk menghentikan server secara tertib dan menunggu pembersihan koneksi asinkronus.

10.2 Deaktivasi Virtual Environment

Kembalikan lingkungan baris perintah ke konfigurasi bawaan sistem dengan perintah:

deactivate
